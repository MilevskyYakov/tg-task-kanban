# #189 — права архивации и восстановления задач

## Диагноз и сохранённая политика

Архивировать и восстанавливать задачу может её автор либо текущий исполнитель, состоящий на активной доске. Роли `admin` и `owner` сами по себе этого права не дают. Отсутствие исполнителя оставляет право у автора. Статус задачи не влияет на право архивации. Доступ к чтению, редактированию полей и изменению статуса не равен праву архивировать: #105 сознательно оставил это ограничение.

Для администратора, который не является автором или исполнителем исходной карточки #189, отказ соответствует политике. Точная identity исторического UI-клика не доказана; контролируемый локальный сценарий воспроизвёл проблему с известной identity. Production-карточка для проб не использовалась.

Дефект находился в UI: кнопка не учитывала авторство и исполнителя. REST преобразовывал отказ общей функции в английский текст, который клиент показывал без преобразования. MCP использовал ту же функцию, поэтому это не отдельная неисправность MCP-ключа. Восстановление имело ту же несогласованность.

## Исправление

- Общая `setTaskArchived` возвращает конкретные русские причины через существующий `TaskActionError`. REST сохраняет HTTP 403, MCP — существующие коды ошибок. Недоступная и отсутствующая задача не раскрываются через подробную причину.
- Проверки выполняются внутри транзакции с блокировкой доски, membership и задачи. Исходные SQL-предикаты прав сохранены; матрица не расширена.
- UI-helper используется в деталях задачи и соседних controls archive/restore. Недоступные кнопки отключены; причина видна и связана с кнопкой через `aria-describedby`.
- Архивирование в деталях ждёт завершения сохранения. При невалидном, несохранённом или конфликтующем черновике запрос архивации не отправляется.
- Зависимости, миграции, ключи и Telegram transport не меняются.

## Проверенный кандидат

Реализация: `ba1a181`. После включения актуального `origin/main` с #193 проверен объединённый commit `4a465b0bc115e4b91e2a58423e2795f431f214df`. Последующая запись этого отчёта не меняет runtime или тесты.

Контур: отдельная локальная PostgreSQL-БД `issue189_release_verify` через Unix socket `/tmp`, штатные миграции, синтетические пользователи и задачи. Изолированный Chrome без личного профиля. Новые браузерные сценарии используют настоящие API handlers через `app.inject` и PostgreSQL; Telegram launch/auth синтетические. MCP проверяется через SDK и локальный HTTP transport.


Результаты:

- `npm run test`: **48 unit + 46 isolation PASS**, без пропусков.
- `lint`, `typecheck`, `build`: **PASS**.
- Playwright: **105 PASS**, включая 12 новых сценариев архива, существующие сценарии архивного проекта, деталей, завершения и изменённого в #193 входа на доску.
- `git diff --check`: **PASS**.

Новая транспортная матрица проверяет archive/restore для автора, исполнителя, другого member/admin/owner и постороннего; неназначенную задачу; frozen/archived доски; повтор состояния; отсутствующую задачу; MCP replay. При отказе сравниваются задача, audit, receipts и notifications. Существующие MCP-regressions дополнительно проверяют read-only режим, scopes и потерю membership.

UI проверяет disabled/reason, успешную архивацию автором и исполнителем, изменение прав или состояния после открытия, ожидание сохранения, отказ сохранения и невалидный черновик. Restore покрыт API/MCP и unit-тестом общего UI-helper; отдельный browser flow восстановления через legacy-поверхность не заявляется. Меню с причиной при ширине 320 px просмотрено: текст читается, переполнения нет.

Локальные логи и снимки: `artifacts/evidence/issue-189/release-*.log` и `release-playwright/`. Исторический разбор и baseline evidence сохранены отдельно; исходные скрипты воспроизведения дефекта не являются тестами исправленного поведения.

Production-выпуск фиксируется отдельно с immutable image ID, backup/restore, actual revision и live readback; локальный PASS не объявляется успешным deploy.
