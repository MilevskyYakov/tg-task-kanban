# #176 — согласованный сценарий нескольких досок чата

## Разрешённый пакет

Владелец явно разрешил записать решения в #176 и выполнить локальную реализацию с проверками. Merge, production, запуск соседних задач, реальные Telegram-отправки и изменение чужих worktrees не разрешены. База: `58924f41b3b5f22ee5a4e3bab6a603d0262c5cde`. Решения согласованы в разговоре; этот документ не является отчётом о завершённой реализации.

## Принятые решения

1. Новая общая кнопка чата открывает выбор досок этого чата; при одной доске — сразу её. При нескольких досках всегда показывается выбор, не последняя открытая. Прямые и старые ссылки сохраняют конкретную доску. Переключение использует существующую панель выбора.
2. «Добавить доску» доступно администратору Telegram в списке досок чата. Форма содержит название и «Создать»; чат уже выбран, общий состав указан пояснением. После создания открывается пустая доска. Сообщение в чат не отправляется.
3. В «Автоматизации» находятся общие настройки чата: «План дня» и «Итоги недели», у каждого своё расписание и выбранные доски. Прежняя доска сохраняет настройки и участие. Новые доски видны, но включаются администратором вручную. Пустой выбор означает отсутствие отправки с явным пояснением в настройках. Исключение из сводки не меняет доступ.
4. Перед созданием второй доски администратор подтверждает существующий состав. Старые приглашения заменяются новыми с предупреждением «Доступ ко всем доскам чата». Прямые ссылки остаются адресными и не выдают права. Общий состав Таски управляется явно: полная синхронизация с составом Telegram не обещается. Проверки административных прав Telegram сохраняются. Исторический доступ не расширяется молча.
5. Длинная сводка делится на нумерованные сообщения без обрезания задач. При неизвестном результате отправки части продолжение останавливается, администратор видит неопределённый результат. Автоматического повтора нет: возможная неполнота до ручной проверки предпочтительнее дублей. Подтверждённый отказ и неизвестный исход различаются.
6. Прежние расписания переносятся без изменений, включая независимые время и часовой пояс дневной и недельной сводок. При конфликте настроек одного типа сохраняется прежний режим; переход к нескольким доскам блокируется до явного выбора администратором общего расписания. Настройки не сбрасываются, прежние публикации не останавливаются.

## Инварианты реализации и приёмки

- Отдельные ID досок, проекты внутри каждой; существующие ID, задачи, проекты и адреса ссылок не переназначаются.
- Создание атомарно и идемпотентно, включая потерянный ответ и конкурентные запросы. Изменившийся состав должен требовать повторного подтверждения, а не принимать устаревшую форму.
- Отзыв общего членства закрывает все доски, прямые ID, API и MCP. Приглашение не должно восстанавливать ранее выданные MCP grants автоматически. Личные и pair-доски не объединяются.
- Одна общая публикация на плановое событие; нет старой параллельной отправки по каждой доске. Снимок длинной публикации и прогресс доставки должны быть устойчивы к повтору процесса.
- Удаление/возврат бота, старые события и supergroup migration затрагивают весь чат; архивные/отозванные состояния не оживают.
- После появления нескольких досок возврат старого кода запрещён без доказательства совместимости. Восстановление старого dump поверх новых пользовательских данных не является штатным rollback.
- Итоговые gates: test (включая отдельную тестовую PostgreSQL), lint, typecheck, build, test:visual, diff --check; для входа также public-entry/cutover. Дополнительно проверка миграции старых данных, multi-board/ACL/MCP/scheduler гонок, UI 320/390 px, 200% текста, клавиатуры, длинных значений и состояний.
- Совместная приёмка #178/#180/#182 и реальный Telegram/device остаются отдельными gates релиза #175. Миграция #178 использует 016; эта задача использует следующий свободный номер после проверки.
