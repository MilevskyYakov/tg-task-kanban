# Таска: профиль, первый вход и обучение

Подготовка #135. Тексты профиля из #132 сохранены дословно в `tasca-bot-profile.json`. Макеты и активы — принятые v0.6/v0.7. Этот документ не означает применения настроек Telegram или разрешения переключить бота.

## Комплект профиля

- Имя, короткое и полное описания: `docs/tasca-bot-profile.json`.
- Аватар: `artifacts/ux/tasca-v07/assets/bot-avatar-512.png`, квадратный оригинал для круглого кропа.
- Описание Mini App: то же короткое описание. Название: «Таска».
- Изображение перед запуском: `artifacts/ux/tasca-v07/assets/group-welcome.png`. Применение в BotFather проверяется отдельно от картинки сообщения.
- Команды: только `/start` и `/help`, без неработающих команд. Scope `all_private_chats`, языки default (`language_code: ""`) и `ru`; неизвестные overrides не удалять. Кнопка меню: «Открыть Таску»; URL не менять до согласованного переключения.
- Подпись «Создано kAIros» не добавляется в повседневные сообщения.

## Шаги пользователя и ответы

| Ситуация | Ответ / действие | Следующий шаг |
| --- | --- | --- |
| Первый `/start` | «Таска — дела под рукой», назначение продукта, обучение в чате и прямые входы | «Как пользоваться Таской» / личные задачи / доска на двоих / группа / помощь |
| Личные задачи | Три шага в приложении: добавить, разобрать бэклог, следить за выполнением | Открыть личную доску и создать задачу |
| Доска на двоих | Создать доску, отправить приглашение, добавить задачи | Второй человек явно принимает доступ к истории; группа не требуется |
| Группа | Добавить бота, открыть сообщение, закрепить вход | Администратор запускает доску; участник видит ожидание |
| Новый бот в прежней группе | Автоматическое приветствие с картинкой v0.7 и кнопкой «Открыть задачи» | Прежняя активная доска открывается без повторного запуска; владелец заменяет закреп |
| Повторный вход по закрепу | Та же доска и сохранённые задачи | Без повторного приветствия и смены токена |
| `/help` или помощь в настройках | Выбор сценария, создание, бэклог, автосохранение, уведомления и повторы | Вернуться к задачам без обязательного повторного обучения |
| Ошибка сохранения | Текущий интерфейс показывает ошибку; помощь не обещает, что запись уже на сервере | Дождаться синхронизации / повторить; при конфликте выбрать версию |
| Нет доступа / приглашение отозвано | Существующий экран отказа без раскрытия чужих данных | Вернуться к своим задачам; запросить актуальное приглашение у владельца |
| Бот удалён из группы | Доска заморожена, данные сохранены | Администратор возвращает того же бота |

Точные runtime-тексты: `apps/api/src/bot-entry.ts`, `apps/api/src/bot-tutorial.ts` и `apps/web/src/bot-entry.tsx`. Инструкция Mini App сохраняется; она не заменяет последовательное обучение в личном чате. Создание задач, приглашения и запуск доски остаются явными действиями.

## Пошаговое обучение в личном чате

Уточнение #135 после /grill: короткое объяснение с переходом к практике, без ожидания выполненных действий и обязательного курса. `/start` предлагает «Как пользоваться Таской» всем, включая новичков; существующим пользователям доступны прежние прямые входы. `/help` позволяет пройти обучение повторно. Отдельный учёт «первого пользователя» не нужен.

1. **Зачем Таска:** договорённости не теряются в переписке; понятно, что сделать, кто отвечает и что готово.
2. **Выбор сценария:** для себя, вдвоём или команда. Выбор меняет только тексты обучения, не создаёт доску и не выдаёт права.
3. **Как устроен выбранный сценарий:** личная приватность, приглашение второго человека или вход команды из группы.
4. **Основные действия:** первая задача, бэклог, исполнитель, срок, переход в работу и завершение. Примеры соответствуют сценарию.
5. **Практика:** личный и парный сценарии открывают прежние `startapp=personal/pair`; групповой — `startgroup=tasks`. Если бот уже в группе, пользователь возвращается к существующей кнопке. Завершение курса не создаёт задач само.

«Далее» и «Назад» меняют одно сообщение, «Пропустить» возвращает прямые входы. На последнем шаге есть «Пройти ещё раз» и «К выбору доски». Нет отправки уроков по расписанию, блокировки продукта или проверки выполнения действий. Старые сообщения не редактируются массово — только конкретное сообщение обучения по нажатию владельца личного чата.

Callback `learn:v1:*` разрешён только для доступного сообщения этого бота с кнопками обучения в личном чате того же пользователя. Неизвестные/некорректные данные, чужие сообщения, inline-mode и группы не обрабатываются как обучение. Текст callback не вставляется в HTML. Используются существующая таблица `telegram_entry_deliveries` и namespace стабильного bot ID; новых миграций нет. Повтор принятого callback, в том числе после restart/ротации токена, не редактирует сообщение снова. Telegram «message is not modified» считается успешным no-op только для `editMessageText`.

Неопределённая отправка и отказ редактирования не запускают автоматический повтор callback: запоздавший webhook не должен возвращать уже пройденный шаг. В клиенте предлагается `/help`; новое явное нажатие имеет новый callback ID. Ошибка `answerCallbackQuery` не повторяет уже выполненное редактирование. Гарантии доставки `/start` и группового приветствия сохраняются. Разные явные нажатия выполняют соответствующие переходы, но завершённость курса и история прогресса не хранятся.

**Обязательное условие deploy:** в `setWebhook.allowed_updates` включить `callback_query` вместе с `message` и `my_chat_member`, затем проверить `getWebhookInfo`. Иначе сообщения появятся, но кнопки обучения не будут получать события. Live webhook этим пакетом не меняется.

## Сообщения после входа

- Групповое приветствие содержит принятый актив, экранированное название доски, инструкцию администратору и одну кнопку. Не редактировать старые закрепы массово.
- Ежедневные и недельные публикации используют footer «Таска». Пустой отчёт оформляется так же. Ссылки строятся из действующего `BOT_USERNAME`, токены не перевыпускаются.
- Назначение и разблокировка сохраняют короткие рабочие сообщения без слогана. Пользовательский текст не интерпретируется как HTML. Opt-in и идемпотентность не меняются.
- Неопределённый результат отправки приветствия не вызывает автоматическую повторную отправку. Реальную доставку нельзя считать проверенной по mock API.

В #164 владелец подтвердил переход на отдельного `@tasca_app_bot` для своей команды и повторно согласовал картинку v0.7. Предварительный `/start` в личке всем участникам не нужен для группового входа; личная доставка остаётся отдельным сценарием. Старые Telegram-ссылки из переписки сохранять не требуется.

Приветствия и ответы на команды учитываются отдельно по стабильному bot ID из префикса токена. Секретная часть токена в ключ доставки не попадает; смена токена или username того же бота не сбрасывает защиту от повторной отправки. Старая запись доставки не блокирует нового бота и не удаляется. Запись приветствия создаётся при обработке добавления бота, а не массовой миграцией досок. Доска, задачи и права остаются прежними; новый запуск использует новый launch link, прежний launch link отзывается существующим механизмом.

Эта подготовка предназначена для согласованного перехода на нового бота, а не для промежуточного выпуска на старой identity. Записи прежнего формата не содержат bot ID, поэтому автоматически приписывать их любому боту нельзя. Одновременная работа двух bot runtimes/schedulers и полный live rollback этим изменением не реализованы.

## Применение внешних полей — отдельный gate

1. До изменения подтвердить `getMe`: точный bot ID и username; не путать старого и нового бота. Переданный кандидатом токен не заменяет production `BOT_TOKEN`.
2. Сохранить текущие поля и локализации без токена в отчёте. Применять только утверждённые имя/описания/команды/аватар. Команды ограничить личными чатами, согласовать default и `ru`, не затереть неизвестные локализованные настройки.
3. Прочитать обратно `getMyName`, `getMyShortDescription`, `getMyDescription`, `getMyCommands` с теми же scope/language_code. Аватар и Mini App проверить в BotFather/клиенте, не объявлять их применёнными по наличию файла.
4. Username, bot ID/token, webhook, menu URL и Main Mini App URL в этой задаче не переключаются.
5. Проверить в согласованном тестовом чате `/start`, `/help`, пару, группу, уведомление и публикацию. Не использовать реальные рабочие группы для массовых проб.

### Пакет оформления до deploy

Цель — только новый `@tasca_app_bot`, не действующий бот. До записи проверить bot ID через `getMe` и совпадение username; при несовпадении остановиться. Токен не передавать в аргументах команд, Issue или логах и не брать автоматически из production `.env`.

- Снять имя, Description, About и команды для default/`ru`, включая известные более узкие command scopes. Совпавшие с JSON поля не переписывать без причины; неизвестные локализации не затирать.
- Имя/описания применять через `setMyName`, `setMyDescription`, `setMyShortDescription` с явным `language_code`. Значения брать дословно из `docs/tasca-bot-profile.json`. После записи читать соответствующие `getMy*` с тем же языком и сравнивать значения.
- Команды применять через `setMyCommands`: `commands` из JSON, `scope: {"type":"all_private_chats"}`, отдельные записи `language_code: ""` и `"ru"`. Для обеих комбинаций выполнить `getMyCommands` и сравнить полный список; конфликтующие более узкие overrides не удалять молча.
- Аватар: `artifacts/ux/tasca-v07/assets/bot-avatar-512.png`, проверить именно профиль нового бота и круглый кроп в Telegram. Изображение перед запуском и оформление Main Mini App — отдельные ручные поля; готовый файл не доказывает применения. URL Main Mini App остаётся на gate финального выпуска.
- В evidence указать только выполненные поля/языки/scopes и результат readback. Отсутствие авторизованного доступа или ручной проверки означает открытый gate, а не PASS.

### Приёмка после deploy

На согласованном Telegram-клиенте проверить начало из `/start`, все три сценария, «Далее», «Назад», пропуск, повтор из `/help`, работу финальных ссылок и двойное нажатие. В группе уроки не появляются. Обновить приложение между шагами и проверить продолжение из существующего сообщения. Отдельно проверить удалённое сообщение/недоступность Telegram и восстановление через `/help`. Не переносить реальные chat IDs, тексты задач или секреты в отчёт. Автоматический тест `apps/api/test/bot-tutorial.test.ts` использует mock Bot API и отдельную БД; это не Telegram/device smoke.

Новый бот `@tasca_app_bot` ответил на read-only `getMe`, а владелец подтвердил отдельную identity. Это не доказательство готовой миграции: live-поля, device smoke и финальное переключение остаются отдельными gates #137/#138/#164. Никакие live-поля и сообщения этой кодовой подготовкой не изменялись.
