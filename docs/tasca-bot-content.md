# Таска: профиль, первый вход и обучение

Подготовка #135. Тексты профиля из #132 сохранены дословно в `tasca-bot-profile.json`. Макеты и активы — принятые v0.6/v0.7. Этот документ не означает применения настроек Telegram или разрешения переключить бота.

## Комплект профиля

- Имя, короткое и полное описания: `docs/tasca-bot-profile.json`.
- Аватар: `artifacts/ux/tasca-v07/assets/bot-avatar-512.png`, квадратный оригинал для круглого кропа.

- Изображение перед запуском: `artifacts/ux/tasca-v07/assets/group-welcome.png`. Применение в BotFather проверяется отдельно от картинки сообщения.
- Команды: только `/start` и `/help`, без неработающих команд. Кнопка меню: «Открыть Таску»; URL не менять до согласованного переключения.
- Подпись «Создано kAIros» не добавляется в повседневные сообщения.

## Шаги пользователя и ответы

| Ситуация | Ответ / действие | Следующий шаг |
| --- | --- | --- |
| Первый `/start` | «Таска — дела под рукой», назначение продукта, четыре кнопки | Личные задачи / доска на двоих / группа / помощь |
| Личные задачи | Три шага в приложении: добавить, разобрать бэклог, следить за выполнением | Открыть личную доску и создать задачу |
| Доска на двоих | Создать доску, отправить приглашение, добавить задачи | Второй человек явно принимает доступ к истории; группа не требуется |
| Группа | Добавить бота, открыть сообщение, закрепить вход | Администратор запускает доску; участник видит ожидание |
| Новый бот в прежней группе | Автоматическое приветствие с картинкой v0.7 и кнопкой «Открыть задачи» | Прежняя активная доска открывается без повторного запуска; владелец заменяет закреп |
| Повторный вход по закрепу | Та же доска и сохранённые задачи | Без повторного приветствия и смены токена |
| `/help` или помощь в настройках | Выбор сценария, создание, бэклог, автосохранение, уведомления и повторы | Вернуться к задачам без обязательного повторного обучения |
| Ошибка сохранения | Текущий интерфейс показывает ошибку; помощь не обещает, что запись уже на сервере | Дождаться синхронизации / повторить; при конфликте выбрать версию |
| Нет доступа / приглашение отозвано | Существующий экран отказа без раскрытия чужих данных | Вернуться к своим задачам; запросить актуальное приглашение у владельца |
| Бот удалён из группы | Доска заморожена, данные сохранены | Администратор возвращает того же бота |

Точные runtime-тексты: `apps/api/src/bot-entry.ts` и `apps/web/src/bot-entry.tsx`. Обучение переиспользует существующие экраны; отдельная машина диалогов, напоминания и автоматические рассылки не нужны. Создание задач, приглашения и запуск доски остаются явными действиями.

## Сообщения после входа

- Групповое приветствие содержит принятый актив, экранированное название доски, инструкцию администратору и одну кнопку. Не редактировать старые закрепы массово.
- Ежедневные и недельные публикации используют footer «Таска». Пустой отчёт оформляется так же. Ссылки строятся из действующего `BOT_USERNAME`, токены не перевыпускаются.
- Назначение и разблокировка сохраняют короткие рабочие сообщения без слогана. Пользовательский текст не интерпретируется как HTML. Opt-in и идемпотентность не меняются.
- Неопределённый результат отправки приветствия не вызывает автоматическую повторную отправку. Реальную доставку нельзя считать проверенной по mock API.

В #164 владелец подтвердил переход на отдельного `@tasca_app_bot` для своей команды и повторно согласовал картинку v0.7. Предварительный `/start` в личке всем участникам не нужен для группового входа; личная доставка остаётся отдельным сценарием. Старые Telegram-ссылки из переписки сохранять не требуется.

Приветствия и ответы на команды учитываются отдельно по стабильному bot ID из префикса токена. Секретная часть токена в ключ доставки не попадает; смена токена или username того же бота не сбрасывает защиту от повторной отправки. Старая запись доставки не блокирует нового бота и не удаляется. Запись приветствия создаётся при обработке добавления бота, а не массовой миграцией досок. Доска, задачи и права остаются прежними; новый запуск использует новый launch link, прежний launch link отзывается существующим механизмом.

Эта подготовка предназначена для согласованного перехода на нового бота, а не для промежуточного выпуска на старой identity. Записи прежнего формата не содержат bot ID, поэтому автоматически приписывать их любому боту нельзя. Одновременная работа двух bot runtimes/schedulers и полный live rollback этим изменением не реализованы.

## Применение внешних полей — отдельный gate

1. До изменения подтвердить `getMe`: точный bot ID и username; не путать старого и нового бота. Переданный кандидатом токен не заменяет production `BOT_TOKEN`.
2. Сохранить текущие поля и локализации без токена в отчёте. Применять только утверждённые имя/описания/команды/аватар. Команды ограничить личными чатами, согласовать default и `ru`, не затереть неизвестные локализованные настройки.
3. Прочитать обратно `getMyName`, `getMyShortDescription`, `getMyDescription`, `getMyCommands` с теми же scope/language_code. Аватар и Mini App проверить в BotFather/клиенте, не объявлять их применёнными по наличию файла.
4. Username, bot ID/token, webhook, menu URL и Main Mini App URL в этой задаче не переключаются.
5. Проверить в согласованном тестовом чате `/start`, `/help`, пару, группу, уведомление и публикацию. Не использовать реальные рабочие группы для массовых проб.

Новый бот `@tasca_app_bot` ответил на read-only `getMe`, а владелец подтвердил отдельную identity. Это не доказательство готовой миграции: live-поля, device smoke и финальное переключение остаются отдельными gates #137/#138/#164. Никакие live-поля и сообщения этой кодовой подготовкой не изменялись.
