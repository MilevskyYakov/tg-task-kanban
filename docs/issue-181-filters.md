# #181 — единая панель фильтров

## Контракт

Кнопка «Фильтры» открывает одну панель на существующем `Sheet`. Категории не сворачиваются и не спрятаны за «Другими фильтрами»:

- **Контекст:** доска, проект, исполнитель.
- **Условия:** поиск, статус, срок, важность, срочность, «Не разобрано».
- **Группировка списка:** по срокам, проектам или приоритету. Это настройка отображения, а не условие отбора.

Значения выбираются нативными `select`; выбранные длинные названия переносятся, категории остаются на месте. Независимые сбросы расположены рядом с условиями. Общий сброс находится в заголовке, кнопка результата закреплена снизу. Если тело не помещается, оно прокручивается вертикально; футер сообщает о продолжении. Поиск остаётся видимым над клавиатурой при изменении `VisualViewport` или высоты layout viewport.

Общий сброс очищает поиск и условия, включая «Только мои» на конкретной доске, но не меняет доску, вид и группировку. Пустой статус означает существующее правило «Без завершённых», а не включение архивных и завершённых задач.

### Данные и совместимость

- Используется `TaskFilters` и nullable-модель оценки #177. Важность и срочность независимы: любая, да, нет, не оценена. «Не разобрано» означает хотя бы одну неоценённую ось и пересекается с остальными условиями; честный нулевой результат допустим.
- «Только мои», конкретный исполнитель и «Без исполнителя» являются взаимоисключающими вариантами. Старые сохранённые противоречивые условия нормализуются; явное отсутствие исполнителя имеет приоритет над конкретным исполнителем, а конкретный — над общим личным срезом.
- Старое `priority=urgent` мигрирует в срочность по #177. Сохранённое `priority=normal` не приравнивается к `urgency=false`: оно отображается отдельным снимаемым условием «Без отметки “Срочная”», включающим неоценённую срочность.
- «Все доски» используют существующий API личных задач. Проект и другой исполнитель здесь недоступны и не применяются, ограничение объяснено. Это не расширение доступа.
- В канбане статус задаётся колонками; сохранённый статус виден в пояснении и не ограничивает канбан. Счётчик складывает результаты всех колонок. Группировка списка сохраняется, но недоступна в канбане и матрице.
- Смена доски использует существующее сохранение фильтров на доску. После успешной загрузки справочников удаляются отсутствующие/архивные проекты и отсутствующие исполнители. Ошибка загрузки не выдаётся за пустой справочник и не очищает выбор. Повторный выбор текущей доски не сбрасывает состояние.
- Счётчик недоступен во время загрузки и ошибки. Повторный или запоздалый ответ сохранённых фильтров не перезаписывает более свежий ввод пользователя.
- Поиск в панели не передаёт фокус поиску на фоне. `Sheet` включает нативные select в обход Tab; Escape, закрытие и mocked Telegram Back возвращают фокус на кнопку открытия. Закрытие не отменяет применённые условия.
- Создание и возврат из карточки не сбрасывают фильтры ради показа созданной задачи. Уведомление о скрытом результате использует те же действующие условия, что список и канбан.

Новых npm-зависимостей, API, миграций и моделей досок нет. Будущая интеграция #176 сохраняет собственный контракт досок; этот пакет не вводит membership или новый общий срез задач.

## Регрессионная проверка

`apps/web/visual/filters.spec.ts` проверяет реальные действия в приложении с детерминированным API/Telegram harness:

- все категории, значения, независимые сбросы и общий сброс;
- счётчики, взаимное исключение исполнителей, важность/срочность/неоценённость, сроки;
- сохранение на сервере mock API и перезагрузку;
- смену досок с устаревшими project/assignee, личный срез всех досок;
- канбан и матрицу с пояснениями неприменимых условий;
- 320/390 px, длинные значения, большие справочники, текст 200%, touch targets от 44 px;
- Tab/Shift+Tab, Escape, возврат фокуса, mocked Back;
- уменьшенный `VisualViewport`: видимость и ввода, и кнопки;
- loading/error/offline, retry, задержанный ответ фильтров, повторный выбор доски;
- read-only доску и старый фильтр приоритета;
- фильтры, поиск, группировку, вид и прокрутку после карточки и создания задачи вне фильтра.

Существующие `priority.spec.ts` и реальный API/DB-сценарий `backlog.spec.ts` переведены на единую панель без сокращения проверяемого поведения. Unit-проверка нормализации находится в `apps/web/test/tasks.test.ts`.

Обязательный общий прогон:

```sh
# TEST_DATABASE_URL должен указывать только на изолированную UTF-8 базу.
DATABASE_URL="$TEST_DATABASE_URL" npm run migrate
npm run test
npm run lint
npm run typecheck
npm run build
PLAYWRIGHT_PORT=45181 npm run test:visual
git diff --check
```

`lint` в этом репозитории является alias typecheck. Harness также содержит API/DB-сценарии, поэтому отсутствие `TEST_DATABASE_URL` — ошибка, а не пропущенный PASS.

## Остаточные границы

- Browser harness не является проверкой реальных Telegram iOS/Android, VoiceOver, системного увеличения текста и экранной клавиатуры. Back и keyboard viewport в нём моделируются.
- В этом macOS headless Chromium стрелки не изменили даже самостоятельный нативный select без React. Программный `selectOption` проверяет применение всех значений, Tab — доступность поля; выбор в системном popup и его Escape/Back остаются device/HITL gate.
- Интеграционный snapshot #176 и production-проверка относятся к общему релизу #175. Соседние worktrees и runtime production не менялись.
- После локальной реализации владелец отдельно разрешил довести #181 до подготовки к деплою, оставив сам деплой в #175. Это основание для commit/PR и передачи результатов; не разрешение отдельного выпуска, автоматического закрытия соседних задач или обхода оставшихся gates.
