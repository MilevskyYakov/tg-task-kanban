## Изменения

- Единые зелёные токены, светлая оболочка, опаловые поверхности, Manrope с локальным файлом и системным fallback. SVG-словесный знак перенесён из принятого пакета без изменений. Обводочный Golos Text не загружается как UI-шрифт.
- Имя «Таска», title и метаданные, словесный знак на существующей внешней заглушке, в помощи и настройках. Внешняя заглушка остаётся заглушкой со старой ссылкой, не превращена в лендинг #136. Сообщения и графика бота #135 не изменены.
- Поиск раскрывается по нажатию, получает фокус; крестик и Escape очищают запрос и возвращают фокус. Запрос сохраняется при открытии карточки и возврате, фильтры остаются доступны.
- Группировка списка перенесена внутрь фильтров, отдельно от условий отбора. Сброс условий не сбрасывает группировку. В канбане настройка группировки списка скрыта.
- Канбан B: нативная горизонтальная прокрутка с CSS scroll-snap, видимый край соседней колонки, быстрые переходы по статусам и управление ArrowLeft/ArrowRight/Home/End. В reduced-motion переходы мгновенные. Свайп не меняет статус задачи; изменение остаётся явным действием через sheet.
- Состояние вида/колонки сохраняется и без вертикального скролла. Прежняя чистая функция распознавания жеста удалена вместе с тестом неиспользуемого пути; заменена проверкой настоящего браузерного скролла.
- Сохранены актуальные автосохранение, потерянные ответы и requestId, восстановление скролла, роли, архив, бэклог, три пути онбординга, проекты и MCP.
- У чекбокса завершения визуальный знак меньше области нажатия: интерактивный размер 44×44. Focus outline контрастный; свечение не заменяет текст состояния.

### Baseline и исправление измерителя

На чистой исходной версии lint/typecheck/build и unit/isolation проходили. Visual baseline: 76 PASS, 6 FAIL. Один сбой — недетерминированный запрос в уже закрытый Fastify при завершении backlog-теста; в последующих полных прогонах не повторился, runtime-фикс этого старого teardown здесь не заявляется. Остальные пять сбоев — требование `events > 10` у Event Timing с порогом 16 ms: быстрые взаимодействия не обязаны попадать в такую выборку.

Измеритель исправлен: считает реальные `input` до следующего `requestAnimationFrame`, сохраняет sparse Event Timing отдельно в `slowEventDurations`. Требование минимальной выборки осталось, но теперь относится к действительно измеренным событиям. Метрика явно обозначена `input-to-next-frame`: это не INP и не гарантированное время физического показа кадра. Исторические JSONL не переписаны; новые записи направлены в папку #134 через `PERF_EVIDENCE_DIR`. До/после численно не сравниваются как одна метрика.

В последнем полном прогоне: p50 1–14 ms, максимум 17 ms, longtask 0 ms на синтетических очередях 50/600 задач. Это измерения локального Chromium, не performance-обещание для телефонов. Сырые данные: `input-perf.jsonl`, старые измерения текущей сессии: `input-perf-legacy.jsonl`.

Проверены реальные композитные пиксели фона списка при 390 и 320 px с временно скрытыми надписями и нижней навигацией. Первичная проверка обнаружила 4,238:1 для вторичного текста на самом тёмном участке. Добавлен тонкий светлый слой `#FFFFFF1F` поверх прежних опорных цветов без нового blur.

После исправления минимальный контраст на проверенном материале:

## Воспроизведение

Из корня репозитория, с установленными зависимостями и Chromium Playwright. Указать **отдельную тестовую** БД, не production:

```sh
export TEST_DATABASE_URL='postgresql://127.0.0.1:5432/tasca_issue134_checks'
export PERF_PHASE=issue-134-after
export PERF_EVIDENCE_DIR="$PWD/artifacts/ux/issue-134-layout"
DATABASE_URL="$TEST_DATABASE_URL" npm run migrate
npm run lint
npm run typecheck
npm run test > artifacts/ux/issue-134-layout/tests.log 2>&1
npm run build
npm run test:visual > artifacts/ux/issue-134-layout/visual-final.log 2>&1
python3 artifacts/ux/issue-134-layout/collect-evidence.py
```

Сборщик evidence использует уже доступный Pillow, как дизайн-пакеты проекта; это не новая runtime-зависимость приложения. Сохраняет контактные листы, копии PNG, проверяет хеши и контраст, падает при недостающем/красном gate. Локальная тестовая БД оставлена для повторной проверки, Vite запускается и останавливается самим Playwright.
