## Реализовано

- `importance` и `urgency`: независимые nullable boolean в задачах и шаблонах, HTTP/MCP, планировщике, интерфейсе и публикациях. Девять комбинаций сохраняются без подмены `null` значением `false`; срок не меняет оценку.
- Миграция `016_task_assessment.sql`: прежний `urgent` становится `importance=null, urgency=true`, `normal` — `null/null`. Backfill и создание полей атомарны; повторный запуск не переписывает явный сброс. Версии задач защищают старые снимки, серии получают собственную revision.
- Общий адаптер legacy-записей под блокировкой текущей строки: проекция `priority`, проверка противоречий, запрет изменения оценки без версии. Другие поля остаются совместимыми. Для применения к будущим повторам проверяются версии задачи и серии; ошибка откатывает задачу и audit вместе.
- Старые MCP create defaults и формат default-cursor/fingerprint сохранены, проверены по прежней канонизации. Новые фильтры и `sort: "priority"` опциональны. Новый keyset cursor сохраняет микросекунды; SQL и web используют одинаковый ключ сортировки, включая date-only в часовом поясе задачи.
- Единое окно «Приоритет», независимые группы «Важная?»/«Срочная?», сброс обоих значений. Минимальные PATCH, отдельное сравнение полей при конфликте, повтор после потери ответа.
- Список по приоритету, отдельный сворачиваемый блок «Не разобрано», матрица с общей рамкой и осями. До трёх задач в квадранте, «Ещё N», возврат из карточки к открытому списку группы. Сохранены фильтры, поиск, список/канбан; известная часть неполной оценки остаётся видимой.
- Старый фильтр `urgent` переносится в срочность «да». Старый `normal` остаётся фильтром «без отметки срочности», а не превращается в осознанное «нет». Некорректные новые значения не сбрасывают остальные сохранённые фильтры.
- Bulk-create сохраняет прежнюю форму payload для совместимости повторов: legacy `normal` на сервере создаёт именно `null/null`.
