## Поведение и границы

- В выбранной доске есть отдельная вкладка «Бэклог» независимо от «Мои». Очередь содержит только неархивные `todo` без исполнителя; фильтр проекта сохраняется, остальные фильтры списка не скрывают очередь. Неназначенные задачи других статусов доступны через «Все» и фильтры; архив автоматически не возвращается.
- `POST /api/boards/:id/tasks/:taskId/claim` назначает только текущего участника. Транзакция использует существующую блокировку доски, блокирует актуальное членство и задачу, оставляет `todo`, добавляет один audit event `claimed`. Конкурент получает 409 и актуальное состояние, а не перезаписывает назначение. Повтор после потерянного ответа показывает уже сохранённое назначение.
- Права обычного PATCH не расширены. Закрыта обнаруженная смежная дыра: отозванный создатель/исполнитель больше не может редактировать или архивировать задачу через сохранённые идентификаторы. Повтор создания также проверяет активную доску и членство до возврата существующего результата.
- «Создать и добавить ещё» сохраняет только доску/проект, очищает остальные поля, закрывает дополнительные настройки, возвращает фокус названию. Обычное создание открывает контекст сохранённой задачи, не теряя её за старыми фильтрами. При неопределённом результате ввод и request ID сохраняются; редактирование временно блокируется до проверки повтором.
- Вставка списка переиспользует идемпотентный POST создания: по одному запросу на непустую строку. Новый bulk API, миграции и зависимости не нужны. Предпросмотр отклоняет названия длиннее 200 символов до отправки. Одинаковые названия допустимы и получают разные request ID.
- После начала отправки контекст и строки фиксируются. Частичный результат показывает подтверждённое количество; повтор отправляет только неподтверждённые строки с прежними ID. Выход в бэклог сохраняет черновик списка в состоянии приложения. Перезагрузка или закрытие WebView не являются долговременным хранилищем черновиков; offline outbox не добавлялся.
