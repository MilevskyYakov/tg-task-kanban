# #82 — production smoke Hermes и завершение

## Кандидат и разрешённый сценарий

Проверенный production commit: `08656edd30c2f1173eba897e8dcff48977f22b9b`.
Клиент: Hermes Agent v0.21.0 (2026.8.31), upstream `bc2154ad`, Python 3.11.15; версия получена через `hermes --version`.
Основной MCP выпущен через PR #90, инструкция Hermes через #91, общая помощь и инструкции других клиентов через #92. Проверка выполнена 2026-09-12 настоящими MCP-инструментами текущей сессии Hermes через HTTPS, с ключом, который владелец создал в приложении и самостоятельно настроил в клиенте.

Владелец потребовал завершить реальную проверку до закрытия #82, а не переносить незавершённый smoke в #83. Изменялась только специально созданная синтетическая задача на разрешённой личной доске. Рабочие задачи не читались и не изменялись; поисковый запрос ограничивался точным уникальным названием тестовой задачи. Ключи, пользовательские идентификаторы и строки подключения в этот отчёт не включены.

## Остальные проверки и границы доказательств

- Read-only, существующая чужая/невыбранная доска, потеря membership, rejoin, permissions, конкуренция с отзывом и fault injection доказаны локальными API/DB/SDK integration tests: [локальный отчёт](issue-82-verification.md). В production их не воспроизводили через дополнительные аккаунты и ключи; полноценная локальная матрица не называется live-матрицей Hermes.
- При завершении повторно выполнены `npm run test` — 32 unit + 13 DB/integration; `npm run lint`, `npm run typecheck`, `npm run build`; полный `npm run test:visual` — 51 passed. Включены два MCP-сценария на 320/390 px, все варианты инструкции, копирование, клавиатура и увеличенный текст. Проверки выполнялись в отдельной временной UTF8 PostgreSQL; кластер остановлен. Полных plaintext MCP-ключей в проверенных логах: 0.
- Production `/health` возвращает `ok`; контейнер healthy; публичный JS содержит новую справку. Данные и миграции проверены при первоначальном релизе; обновления #91/#92 не меняют API/БД.
- Claude Code и Codex: проверены документация, регистрация конфигурации в изолированных каталогах и shell-ввод/экспорт. Реальный доступ этих клиентов к production-задачам не проверялся. Claude.ai/Desktop требует доступной не всем beta Request headers; организационный ключ может быть общим.
- Реальная новая команда, iOS/Android Telegram, групповая доставка и общий продуктовый цикл остаются в #83. Их результаты не подменяются MCP smoke.
- Неподтверждённое сохранение прежних review roots в `.pen` остаётся ограничением исходного UX-артефакта; сохранённые PNG/PDF и реализованный UI не выдаются за проверку этого исходника.

## Состояние после проверки

Синтетическая задача оставлена завершённой и без срока. Удаление через MCP не входит в контракт; задача не удалялась обходным путём.
После отказов отозванному ключу независимый read-only SQL readback подтвердил `done`, версию `3` и отсутствие срока.

Старый ключ отозван и недействителен. После предложения восстановить рабочее подключение владелец прямо отказался создавать новый ключ сейчас и отложил повторное подключение. Это сознательно отключённый клиент, а не неисправность сервера и не незавершённая попытка настройки. Не восстанавливать доступ автоматически. Для будущего использования потребуется новый ключ и его настройка владельцем.

#82 завершается на основании реализации, автогейтов и фактического Hermes E2E выше. #83 и родитель #75 остаются открытыми. Этот документ не объявляет общую продуктовую или универсальную межклиентную приёмку завершённой.
