# #191 — восстановимое удаление досок

## Согласованные решения и границы

Пользователь согласовал модель и разрешил записать решения в Issue #191 и начать реализацию в текущем worktree. Изначально commit, push и deploy не были разрешены; после локальной проверки пользователь отдельно поручил выполнить commit/PR/deploy. Удаление существующих production-досок для проверки по-прежнему запрещено.

- Удаление восстановимое, без физической очистки в первой версии. Данные хранятся вместе с исходными идентификаторами; сроки автоматической очистки не вводятся.
- Удалённая доска скрыта из рабочих списков, сводок, обычных ссылок и MCP. Задачи, проекты, комментарии, вложения, история и зависимости сохраняются.
- Повторы останавливаются. Восстановление явное, без автоматического возобновления публикаций и доступов.
- Удалять и восстанавливать доску чата может текущий администратор Telegram с доступом к доскам чата; парную — только владелец. Членства недостаточно.
- Личная доска остаётся постоянной и не удаляется. Пустые и непустые общие доски удаляются по одной модели.
- Последнюю доску чата удалять можно. Чат и бот остаются; публикации прекращаются. Вместо автоматического пересоздания доступны создание или восстановление доски.
- Удаление одной доски не меняет данные и доступы соседних досок. Старые ID не переназначаются. Нового MCP-инструмента удаления нет.
- Перед подтверждением интерфейс показывает состав затронутых данных и последствия; отмена ничего не меняет.
- Только изолированные локальные проверки. Production, Reels, ключи и роли существующих пользователей не затрагиваются.

## Проверка

Ниже зафиксирована локальная проверка до разрешения публикации; на этом этапе выпуска не было. Пользователь отдельно разрешил `npm ci` по lockfile и запуск изолированного PostgreSQL. Новых зависимостей нет. Результаты последующей интеграции и выпуска фиксируются отдельно.

### Реализация

- Миграция `018_board_deletion.sql`: отметка удаления, версия жизненного цикла, журнал подтверждённых операций и общее представление доступных членств. Физического удаления нет; корневая запись чата сохраняет связи соседних досок.
- `board-deletion.ts`: единая проверка прав удаления/восстановления, снимок состава данных, защита от устаревшего подтверждения, транзакция и идемпотентный requestId. Повтор старого удаления после восстановления не удаляет доску снова.
- UI: действие в настройках конкретной доски, подтверждение с количествами данных, отмена, повтор проверки после потери ответа, раздел «Удалённые доски». После удаления открытая вкладка обновляет доступные доски с сервера, а не скрывает весь чат.
- Обычное чтение/изменение задач, проектов, комментариев, чек-листов и вложений, личный список задач и MCP учитывают удаление. Новых MCP-инструментов нет.
- Повторы ставятся на паузу. Удалённая доска исключается из выбора публикаций; ожидающая публикация с её данными отменяется. Уже начавшаяся доставка заканчивается до подтверждения удаления под общей блокировкой чата. Сводки оставшихся досок продолжаются.
- Адресные ссылки и приглашения удаляемой доски отзываются. Общие вход и приглашение чата сохраняются, пока есть соседние доски; при удалении последней доски общее приглашение отзывается. Общий вход остаётся адресом управления для текущих участников, но не выдаёт доступ.
- Восстановление возвращает данные с прежними ID текущим участникам. Оно не возвращает отозванное членство, старые приглашения, MCP-разрешения, повторы и включение в сводки. Общее членство чата не удаляется и не пересоздаётся ради одной доски.
- Возврат бота не восстанавливает удалённые доски. Перенос чата в supergroup не может считать ранее удалённую доску свободным черновиком и переназначить её ID.

Те же шесть сценариев с тем же результатом запущены на копии `git archive 5c6fea4`, без изменений #191, с теми же зависимостями и БД:

`PLAYWRIGHT_PORT=4175 node_modules/.bin/playwright test -c artifacts/evidence/issue-191-runtime/baseline/apps/web/playwright.config.ts settings-autosave.spec.ts --grep 'success|legacy.*upgrade'`

Порогов и ожиданий существующих тестов не меняли. Несвязанное автосохранение не исправляли. Это не блокер проверенных сценариев удаления, но оснований объявлять весь UI-suite зелёным нет.
