## Макет

1. На экране открытой доски под существующим действием «Доступ» показано «Вход в эту доску / Получить сообщение для пересылки». Выбор доски повторять не нужно.
2. Представлено содержимое готового сообщения бота: обложка Таски, название доски, объяснение, ссылка в тексте и дублирующая кнопка. В макете ссылка — подписанный placeholder, а не действующий Telegram URL. Экран не имитирует подтверждённую доставку или внешний вид конкретного Telegram-клиента.
3. Получатель без доступа видит просьбу запросить отдельное приглашение. Название закрытой доски и задачи на этом экране не выводятся.

Использованы реальные `AppShell`, `TasksScreen`, `ActionRow`, `PairScreen`, иконки, Manrope и CSS проекта. `preview.tsx` рендерит статический HTML без hydration; серверный offline fallback скрыт только в прототипе для демонстрации нормального online-состояния. Никакие сетевые сценарии этим не проверяются. Кнопки переходов между макетами не подключены к API/Telegram.

## Воспроизведение

Из корня репозитория:

```sh
./node_modules/.bin/tsx --tsconfig apps/web/tsconfig.json artifacts/ux/issue-180/preview.tsx
./node_modules/.bin/tsc --noEmit --jsx react-jsx --target ES2022 --module ESNext --moduleResolution Bundler --skipLibCheck --allowSyntheticDefaultImports artifacts/ux/issue-180/preview.tsx
git diff --check
```

Скрипт использует установленный Chrome через Playwright `channel: 'chrome'`, новый изолированный headless-профиль, без подключения к пользовательскому браузеру. Все запросы перехватываются локальным route; неразрешённые запросы блокируются. Реальные боты/аккаунты не используются.

Результат находится в `artifacts/visual-evidence/issue-180/`:

- `index.html` — локальный обзор трёх экранов; открыть в браузере.
- `overview.png` — общий снимок.
- `{board,message,denied}-{320,390}-{100,200}.png` — отдельные размеры и масштаб текста.
- `checks.json` — версия браузера и результаты проверок.

## Готовность среды

Node `v22.22.3`, npm `10.9.8`. Установлены зависимости из lockfile командой `npm ci --include=dev --ignore-scripts`; первый `npm ci --ignore-scripts` не предоставил devDependencies. Новые зависимости и автоматические security-upgrades не добавлялись. npm сообщил 4 уязвимости существующего dependency tree (1 moderate, 2 high, 1 critical); причины и применимость отдельно не исследованы.

Для реализации создана отдельная локальная PostgreSQL-база `tasca_issue180_test` на `127.0.0.1:5432`; миграции применены только к ней. Production-БД и реальные credentials не использовались.

Playwright Chromium из cache отсутствует; установленный системный Chrome используется через `PLAYWRIGHT_CHANNEL=chrome`, в изолированном headless-профиле. Проверка видеозаписи использует существующий системный FFmpeg через symlink в игнорируемом test cache, без новой установки.

## Границы приёмки

- Получение сообщения с картинкой, адресный launch без membership и усиление старого входа реализованы. Результаты проверок относятся к локальному коду, не к Telegram-клиенту.
- Совместимость нескольких досок одного чата остаётся интеграционным gate #176/#175; текущая схема допускает одну доску на чат.
- Получить отдельное разрешение тестового бота/чатов/аккаунтов и проверить фактическое получение, пересылку и открытие на реальных клиентах.
- Merge и production deployment остаются отдельными разрешениями. Реализация и визуальное согласование не закрывают Issue автоматически.
