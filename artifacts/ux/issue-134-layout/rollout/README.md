# #134 — распространение принятого визуального направления

После положительной оценки главного экрана и создания задачи пользователь разрешил перенести решение на остальные поверхности Mini App. Реализация выполнена локально, без commit, push, merge или deploy. Визуальная приёмка новых экранов и проверка реальных Telegram-клиентов остаются открытыми.

## Изменения

- Канбан B: самостоятельные светлые карточки на спокойной подложке колонки, мягкие тени и округлое действие смены статуса. Горизонтальное листание, видимый край соседней колонки, вкладки и клавиатурное управление сохранены. Срочность по-прежнему обозначена текстом, а не только цветом.
- Детали задачи: заголовок и статус выделены в локально окрашенный блок; свойства, описание, чек-лист и комментарии разделены на самостоятельные поверхности. Автосохранение, readonly, история, GitHub и работа с описанием не изменены.
- Настройки: светлые карточки и формы, локальный акцент рабочего пространства, округлые элементы дочерних экранов. Поля выбора не оформляются как основные действия.
- Окна выбора и фильтры: отдельные варианты, мягкая глубина, согласованные активные состояния и основные кнопки. Группировка остаётся внутри фильтров.
- Бэклог и MCP: те же поверхности и контролы; поведение API, права, выдача и отзыв ключей не изменены.
- Использованы существующие компоненты, CSS и установленный стек; новых зависимостей нет. Бот и лендинг не перерабатывались.

## Evidence

- Актуальная коррекция композиции: `details-layout.png`, отдельно `details-layout-320.png` и `details-layout-390.png`. Декоративный знак убран из заголовка деталей, текст получил полную ширину и прежний крупный размер. Статус остаётся кнопкой; прогресс представлен подписью и полосой без второй капсулы. В панели комментария кнопки центрируют SVG через grid; кнопка отправки имеет размер 44×44 px. Пройдены 21 проверка деталей, lint/typecheck и build (`details-layout.log`, `lint-layout.log`, `build-layout.log`), а также `git diff --check`. Проверяются общая линия статуса и прогресса, равные отступы заголовка и центрирование самолётика. Полный набор и реальные устройства после этой правки не проверялись; визуальная приёмка владельца остаётся открытой.
- Предыдущая попытка `details-wrap-320.png` / `details-wrap-390.png` с уменьшенным заголовком отвергнута владельцем. Эти снимки, обзорные листы и `after/` ниже сохранены как история, не текущая композиция деталей.
- `preview-390.png`: канбан, детали задачи и настройки при ширине 390 px.
- `preview-320.png`: те же экраны и фильтры при ширине 320 px.
- `before/`: семь исходных снимков перед этим этапом.

Это реальные рендеры изолированного Chromium с тестовыми данными, не макеты и не снимки реального Telegram. Секретные поля MCP скрываются существующим screenshot style; сторонние изображения в этот пакет не включены.

## Проверки

- `npm run lint`, `npm run typecheck`: успешно, `lint.log`, `typecheck.log`.
- `npm run test`: 32 unit и 13 integration, `tests.log`. Использована отдельная локальная БД `tasca_issue134_checks`.
- `npm run build`: успешно, повторено после финального изменения CSS, `build.log`.
- `npm run test:visual`: 89 проверок успешно, `visual-final.log`. Покрыты канбан, поиск, фильтры, создание, автосохранение, ошибки, readonly, настройки, бэклог, MCP, укороченный viewport и имеющиеся fallback/200%-text сценарии.
- После финального исключения строк выбора из CSS основных кнопок повторены четыре проверки `settings.spec.ts`, `settings-final.log`. Полный набор после этой узкой правки не повторялся.
- В существующие тесты добавлены проверки зазоров карточек, отдельных поверхностей деталей, теней и отсутствия основной заливки у поля выбора. Добавлены снимки нижних блоков и дочерних настроек.
- `git diff --check`: успешно.

Просмотрены реальные снимки 390/320 px, итоговый сравнительный лист, нижняя часть деталей, форма автоматизации, бэклог и MCP. При просмотре исправлена конкуренция CSS-селекторов: поля выбора автоматизации наследовали оформление основной кнопки. Проверки браузера не заменяют визуальную приёмку владельца, реальную экранную клавиатуру, iOS/Android WebView или полный аудит доступности.
