## Полный браузерный прогон: честный остаток

Выполнен весь текущий набор:

```sh
TEST_DATABASE_URL='postgresql://milevsky.yakov@127.0.0.1:5432/tasca_issue170_local_checks' \
PLAYWRIGHT_JSON_OUTPUT_NAME="$PWD/artifacts/visual-evidence/issue-170/browser-results.json" \
PERF_EVIDENCE_DIR="$PWD/artifacts/visual-evidence/issue-170" PERF_PHASE=issue170-candidate \
PLAYWRIGHT_PORT=4180 npm run screenshots -w @task/web -- --reporter=line,json
```

Результат первого полного прогона: **243 PASS / 6 FAIL / 0 skipped**. Этот результат не заменён задним числом успешными выборочными повторами.

1. **Три проверки увеличения текста лендинга. Исправлены.** После `addStyleTag` немедленный `getComputedStyle` иногда ещё возвращал прежний размер. Отдельный воспроизводящий прогон на настоящей сборке показал 16/15 px сразу после вставки стиля и 32/30 px после кадра. Тест теперь ждёт именно требуемый размер через `expect.poll`, не ослабляя требование удвоения. После этого все проверки лендинга прошли дважды: `landing-final-results.json`.
2. **Branding 320: overflow в состоянии загрузки/ошибки.** Не относится к новому лендингу; в тот момент показан другой экран. Повторилось на архиве исходного commit с тем же `contextOptions.reducedMotion`, без изменений кода приложения: `baseline-repeated-results.json`.
3. **Scroll restore 320: начальное прокручивание до 1200 px иногда останавливалось на 1106 px.** Ошибка возникает до открытия карточки и проверки возврата. Воспроизведена на исходном commit с тем же режимом браузера. Сценарий и приложение не менялись.
4. **MCP 320: единичный сбой keyboard focus в диалоге выбора досок.** Не повторился в целевых запусках candidate и baseline. Причина не установлена; не объявляется исправленным и не маскируется повышением retries.

Для сравнения исходники извлечены `git archive HEAD` в Git-ignored `artifacts/visual-evidence/issue-170/baseline/`; рабочая ветка и файлы пользователя не переключались. Для baseline добавлен только отдельный runner config, задающий тот же reduced-motion режим. Первый baseline-прогон трёх подозрительных сценариев: 3/3 PASS. Повтор каждого трижды: 7 PASS / 2 FAIL; повторились branding и scroll. На candidate повтор этих же сценариев трижды: 6 PASS / 3 FAIL; branding дважды и scroll один раз. Это подтверждает нестабильность, а не полный зелёный gate.

Полный набор после финальной правки ожидания в тесте не запускался заново: эта правка затрагивает только проверенный дважды `landing.spec.ts`. Неизменённые сценарии и их непокрытый остаток сохранены выше. Для общего разрешения выпуска потребуется отдельный полностью зелёный итоговый gate или явное решение по выявленным сбоям; новых задач без команды не создано.
