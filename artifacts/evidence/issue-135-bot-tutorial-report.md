## Что реализовано

- `/start` предлагает «Как пользоваться Таской» и сохраняет прямые входы в продукт; `/help` позволяет пройти обучение повторно.
- Пять шагов в личном чате: польза продукта, выбор сценария, устройство выбранного сценария, основные действия, практика. Для личных дел, пары и группы используются разные примеры и финальные ссылки.
- «Далее», «Назад», «Пропустить», повторное прохождение. Редактируется одно сообщение обучения, без рассылки, обязательного курса, создания задач или ожидания действий пользователя.
- Существующие `startapp=personal/pair/group/help`, инструкции Mini App и групповые входы сохранены. Финал группового обучения использует действующий `startgroup=tasks`; для уже подключённой группы указано возвращение к существующей кнопке.
- Callback принимается только для доступного сообщения этого бота с кнопками обучения в личном чате того же пользователя. Неизвестный/некорректный callback, группа, чужой пользователь/бот, постороннее или недоступное сообщение не редактируются. Пользовательский ввод не попадает в HTML.
- Дедупликация переиспользует `telegram_entry_deliveries` и стабильный bot ID. Повтор после рестарта или ротации токена не меняет сообщение вновь. Новых миграций и зависимостей нет.
- Успешный повтор того же содержимого (`message is not modified`) распознаётся только для `editMessageText`. Неопределённый результат и отказ кнопки не вызывают автоматический повтор; для нового явного действия используется новый callback ID. Запоздавший повтор не отменяет более поздний шаг. Сбой ответа callback не отменяет успешное редактирование.
- В README и обоих runbooks добавлен `callback_query` в обязательный webhook allowlist и readback. Устранено расхождение command scope: `all_private_chats`, default (`""`) и `ru`.

Реализация: `apps/api/src/bot-tutorial.ts`, `bot-entry.ts`, webhook в `app.ts`, классификация ответа в `telegram.ts`. Регрессия: `apps/api/test/bot-tutorial.test.ts` в штатном `npm run test:isolation`; смежные гарантии проверяет `chat-board.test.ts`.

Production-конфигурация и секреты действующего бота не читались и не менялись. Приватные снимки до/после сохранены в ignored evidence с правами 0600, секрет не выводился и не публиковался.

- Имя, Description и About для default языка уже совпадали с утверждённым JSON; сохранены без повторной записи.
- Пустые русские локализации имени, Description и About заполнены утверждёнными значениями. Каждое поле прочитано обратно с `language_code: "ru"` и сравнено с JSON.
- `/start` и `/help` применены для `scope: all_private_chats`, отдельно для `language_code: ""` и `"ru"`; обе комбинации прочитаны обратно и полностью совпадают. Общий default scope не менялся; неизвестные локализации не затрагивались.

## Сбои окружения и ограничения

- Первая попытка запуска PostgreSQL остановилась: путь Unix socket превышал лимит macOS. Кластер запущен только по TCP loopback, Unix socket отключён; production не затронут.
- Первый фоновый browser-запуск не унаследовал `TEST_DATABASE_URL` и остановился при сборе тестов. Повтор использует явную loopback URL. Для передачи reporter через вложенные npm scripts необходим дополнительный `--`; неуспешный запуск не засчитан.
- `npm audit` сообщает об уже существующей moderate уязвимости Fastify: GHSA-4mh8-r7rc-xpvc (HTTP/2 trailer responses). Lockfile и версии зависимостей этим изменением не менялись; автоматический `audit fix` не выполнялся. Это отдельный остаточный риск, не результат обучения.
- Browser emulation и mock Bot API не доказывают работу кнопок в реальном Telegram. Доступные поля профиля применены и прочитаны обратно отдельно, как описано выше; Main Mini App, изображение перед запуском и клиентская приёмка остаются открытыми. Подробный пакет полей и ручной приёмки — `docs/tasca-bot-content.md`.
