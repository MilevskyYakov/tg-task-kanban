## Не скрытые сбои окружения

Первый setup использовал неверный рабочий каталог; внесённая этим копия ассета в base checkout восстановлена из его HEAD, временная тестовая БД остановлена и перенесена в task workspace. Base checkout сохранил только исходный untracked PNG. Production не затронут.

Первый `npm ci` унаследовал production omission и не поставил dev types; исправлено явным `--include=dev`. Первый initdb без locale создал SQL_ASCII: кириллические длины/регистры дали два тестовых отказа. Создана отдельная UTF8/en_US.UTF-8 БД, проверки прошли без изменения приложения. Полный unsharded browser прогон прервался по лимиту инструмента; он не засчитан. Shard 3 сначала упал на MCP harness, жёстко ожидающем порт 4173, при запуске на 4195. На штатном порту все 12 тестов прошли; исправление переносимости harness относится к адресной подготовке #137.

Локальные raw logs/reports: `artifacts/evidence/tasca-preparation-runtime/`. Изображения: `artifacts/visual-evidence/`. Build предупредил о крупном JS chunk; сборка успешна, это не доказательство оптимального веса лендинга.

## Внешняя граница

Read-only Bot API подтвердил `@tasca_app_bot`: имя и оба описания уже соответствуют принятым; команды пусты, menu button типа `commands`, webhook отсутствует. Эти поля существовали до нашей записи; ничего не применялось. Аватар/Main Mini App/локализации и физические Telegram-клиенты не проверены.

#135 остаётся OPEN до разрешённого применения внешних полей и реальной приёмки. Подготовка кода не означает готовую миграцию. Новый вопрос идентичности и старых входов выделен в #164; #138 заблокирована. Deploy по решению владельца отложен до готовности внешних материалов/настроек.
