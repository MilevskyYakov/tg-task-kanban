# Таска

Задачи для себя и команды в Telegram. Действующий вход — `@tasca_app_bot`, основной адрес — `https://tasca.kairos-ai.ru`. Переключение зафиксировано в [cutover runbook](docs/tasca-cutover-runbook.md); новое обновление кода само по себе не разрешает менять бота или адреса.

## Локальный запуск

Требования: Node.js 22+, Docker.

```bash
cp .env.example .env
# Заполнить BOT_TOKEN, POSTGRES_PASSWORD, DATABASE_URL, SESSION_SECRET и WEBHOOK_SECRET
docker compose up -d db
npm install
DATABASE_URL=postgres://task:***@localhost:5432/task npm run migrate
npm run dev
```

Web shell собирается командой `npm run build`; API слушает `127.0.0.1:2240`. Основной production-вход — `https://tasca.kairos-ai.ru`; `https://task.kairos-ai.ru` сохранён как совместимый HTTP/MCP alias без redirect.

## Проверки

```bash
npm run lint
npm run typecheck
npm run test:unit
TEST_DATABASE_URL=postgres://task:task@localhost:5432/task npm run test:isolation
npm run build
DATABASE_URL=postgres://task:task@localhost:5432/task npm run migrate
```

Интеграционный тест изоляции обязателен и падает без `TEST_DATABASE_URL`. Для полного browser/API/DB gate также запустите `npm run test:visual` с этой переменной. Используйте только отдельную тестовую PostgreSQL, заранее применив к ней миграции (`DATABASE_URL="$TEST_DATABASE_URL" npm run migrate`); не направляйте тесты или тестовые миграции в production.

Бэклог и быстрое добавление (#78): общая очередь `todo` без исполнителя, атомарное «Взять себе», серия задач с сохранением доски/проекта и вставка списка с безопасным повтором. Локальная проверка и границы: [`docs/issue-78-verification.md`](docs/issue-78-verification.md).

Направления чата (#176): несколько досок, подтверждённый общий состав, отдельный выбор досок для дневной и недельной сводок, доставка по частям без автоматического повтора при неизвестном результате. Проверки и граница миграции: [`docs/issue-176-verification.md`](docs/issue-176-verification.md). После миграции 017 прежний runtime несовместим; простой возврат старого image запрещён.

В списке «Доски чата» администратор может получить общую ссылку для уже подключённой группы и самостоятельно разместить её в Telegram. Ссылка не выдаёт доступ, не заменяет старые адресные ссылки и не вызывает отправку сообщения ботом.

Полный production runbook, backup/restore и pilot gate: [`docs/release-runbook.md`](docs/release-runbook.md) и [`docs/pilot-checklist.md`](docs/pilot-checklist.md). Release gate нового Telegram UX: [`docs/issue-37-release-gate.md`](docs/issue-37-release-gate.md).

Профиль и обучение: [содержание бота](docs/tasca-bot-content.md). Адреса, совместимость и история переключения: [cutover runbook](docs/tasca-cutover-runbook.md); его подготовительные таблицы не описывают текущий runtime. `PUBLIC_URL_ALIASES` допускает только точные согласованные origins; шаблон `.env.example` не переключает действующие адреса. Совместимость старого HTTP/MCP-входа не означает работоспособность старых Telegram-ссылок: использовать нового бота, групповой закреп заменяет владелец. Для проверки маршрутов собранного лендинга: `npm run build`, затем `npm run test:public-entry` с изолированной `TEST_DATABASE_URL`.

## Приём Telegram: polling

Текущий транспорт — polling через единственный `telegram-poller`: он получает `getUpdates` и передаёт события во внутренний защищённый `/api/telegram/webhook`. Этот endpoint сохраняется; наличие пути `webhook` не означает входящий webhook от Telegram. Устройство, проверки, дальнейшие deploy и откат описаны в [Telegram polling runbook](docs/telegram-polling-runbook.md).

**Не включать webhook (`setWebhook`), пока работает consumer:** при непустом webhook URL приёмник блокируется. Не запускать второй poller и не вызывать дополнительный `getUpdates` для диагностики. В polling-режиме пустой URL в `getWebhookInfo` — норма. Возврат к входящему webhook допустим только как отдельно разрешённый откат транспорта по runbook: сначала остановить consumer, затем восстановить сохранённые options без сброса очереди (`drop_pending_updates=false`) и проверить результат. Обычный deploy приложения не переключает транспорт.

`/start` предлагает пошаговое обучение в личном чате и прямые входы в личные задачи, доску на двоих и доску для группы. `/help` повторно запускает обучение; «Помощь» в настройках приложения сохраняет инструкции Mini App. Poller получает `message`, `my_chat_member` и `callback_query`, включая кнопки обучения. Проверка доставки требует настоящей команды и ответа по runbook; health контейнера не заменяет Telegram/device-приёмку.

Боту нужны права читать состав чата для серверной проверки актуального статуса администратора. При первом подключении новой группы бот отправляет одно фото с подписью «Таска · {Название доски}», краткой инструкцией и кнопкой «Открыть задачи». Пользователь закрепляет сообщение сам. Новый общий `startapp`-токен ведёт на первичную настройку для администратора; для участника с доступом одна доска открывается сразу, несколько — через выбор доски этого чата. Адресные ссылки не выдают права: для нового участника нужно явное принятие приглашения. Ранее выданные адресные ссылки действующего бота продолжают открывать свою доску, если доступ уже есть; это не перенос ссылок прежнего бота. Повторная доставка события во внутренний webhook и повторная активация не меняют успешную ссылку; старые закрепы не мигрируют. Неопределённый результат отправки требует ручной проверки, а не автоматической повторной рассылки. Историческая проверка входа и Telegram device gate: [`docs/issue-80-verification.md`](docs/issue-80-verification.md); изменения поведения — в проверке #176.

В разделе **Настройки → Рабочее пространство → нужная доска** действие «Переслать ссылку на доску» открывает личный чат бота с выбранной доской; при необходимости нужно нажать «Начать». Действие доступно для активных общих досок и архивных досок на двоих. На главном экране задач и в «Автоматизации» его нет. Бот подготовит сообщение для пересылки. Доступ к доске не изменится. Бот присылает обложку Таски, название, ссылку в подписи и кнопку. Пересланная ссылка открывает только эту доску и только при существующем доступе; приглашение остаётся отдельным действием. Старые групповые кнопки допускают нового пользователя только после серверного подтверждения его участия в соответствующей Telegram-группе; для гарантированной проверки бот должен быть администратором. Ошибка проверки не выдаёт доступ. Контракт и непроверенные Telegram/device-границы: [`docs/issue-180-verification.md`](docs/issue-180-verification.md).

## Production deploy

Только после отдельного разрешения и выполнения [release gates](docs/release-runbook.md). Для существующей установки сохранить действующий polling по [runbook](docs/telegram-polling-runbook.md): не регистрировать webhook после обновления app. На сервере `/opt/tg-task-kanban`: создать `.env` по `.env.example`, добавить `POSTGRES_PASSWORD`, затем:

```bash
git pull --ff-only
docker compose build
docker compose up -d db
docker compose run --rm app node apps/api/dist/migrate.js
docker compose up -d
curl --fail http://127.0.0.1:2240/health
```

Секреты, `initData` и cookie не логируются. PostgreSQL не публикуется наружу.

## Подключение AI-клиента (MCP)

Оценка задач и серий: независимые `importance` и `urgency` (`true` / `false` / `null`). `null` означает «не оценено», а не «нет»; срок не меняет оценку. Для изменения оценки необходима актуальная `expectedVersion` из чтения задачи или серии. Старый `priority` остаётся проекцией срочности для совместимости. `list_tasks` поддерживает отдельные фильтры `importance`/`urgency` (`any`, `true`, `false`, `unassessed`), `unassessed: true` и `sort: "priority"`; без `sort` сохраняются прежний порядок и курсоры. Миграция, защита от перезаписи и порядок rollout: [контракт #177](docs/issue-177-priority-contract.md).

Для новых MCP-подключений (Hermes и других) используется `https://tasca.kairos-ai.ru/mcp` с персональным ключом. Прежний `https://task.kairos-ai.ru/mcp` сохранён без redirect; существующие ключи, scopes и grants не меняются. Ключ создаётся в приложении: **Аккаунт → Подключения → Добавить подключение** — выбрать название, свои доски и режим (только чтение или чтение и изменение). Полный ключ показывается один раз.

Подключение Hermes:

```bash
hermes mcp add task_kanban --url 'https://tasca.kairos-ai.ru/mcp' --auth header
```

Ключ сохраняется в `~/.hermes/.env` как `MCP_TASK_KANBAN_API_KEY`. Доступ отключается отзывом подключения в приложении в любой момент. Контракт инструментов, идемпотентность и границы: [`docs/issue-82-mcp-contract.md`](docs/issue-82-mcp-contract.md); поверхность включает карточки (полное редактирование, claim, архив, комментарии, чек-лист, вложения-ссылки), проекты и повторяющиеся задачи (создание, пауза, архив серии).
